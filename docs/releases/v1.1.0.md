Caddy UI 1.1 adds a **Domains** area for the domains you own at Porkbun, and ties it into the Caddyfile so the DNS records your sites need stay in step with Caddy. Everything is optional: without Porkbun keys the UI behaves exactly as in 1.0.

## Highlights
- **Domains list and Overview**: expiry, auto-renew, lock, WHOIS privacy and API access per domain; auto-renew for many domains at once; account credit.
- **DNS editor**: a form for every common record type, changes staged in a pending tray, reviewed together and applied in order; import and export as a BIND zone file or JSON.
- **History**: Porkbun's DNS restore points, a diff against the live zone, restore, and the preflight safety check.
- **Registry**: nameservers, glue records and DNSSEC.
- **Forwarding and SSL**: URL forwards (301, 302, 307, masked) and the Porkbun-issued certificate bundle.
- **Caddy tie-in**: detects the `caddy-dns/porkbun` plugin, guided forms for DNS challenges and wildcard sites, and a per-site check that each site has a DNS record pointing at this server, with a one-click fix.
- **Activity**: every change the UI made, with the state before it.
- `deploy/caddy/Dockerfile` builds Caddy with the Porkbun plugin.

## Fixes
- The editor no longer flags valid Caddyfile as an error: a DNS provider block such as `tls { dns porkbun { … } }`, `-1` for `flush_interval`, `stream_timeout`, `stream_close_delay` and `propagation_timeout`, and the block of a plugin module the schema does not list (`lb_policy`, `issuer`, `get_certificate`).
