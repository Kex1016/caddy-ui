Caddy UI 1.2 makes Overview and Sites open at once and adds a **Settings** page, so most of what used to need a compose change and a restart is now a field. Nothing is required: the environment still works as before, and a value saved in Settings only wins until you reset it.

## Highlights
- **Fast pages**: Overview and Sites show their shell immediately and stream the charts in, however large the database is. The collector keeps a snapshot, and a `Server-Timing` header on every page says where time goes.
- **Settings page**: probe and metrics intervals, retention (with a preview of what the next clean-up deletes), probe timeout, certificate warning days, revisions and backups to keep, time zone, public address, Porkbun switches and the update interval, all applied without a restart. Every other variable is shown with a check, and every change is listed with who made it.
- **Check everything**: one button runs the health checks (admin API, metrics, access log, data directory, Porkbun, collector jobs, slowest page loads).
- **Caddy helpers**: turn on per-host metrics and the JSON access log as a reviewed Caddyfile change.
- **Data and storage**: size per table against free space, prune now, compact, and download a backup.
- **Per-site probe options**: skip a site, probe another path, or count a status as up.
- **Discord notifications**: site and upstream down and up, certificates near expiry, Caddyfile changed outside the UI, update applied or rolled back. Editable Components v2 templates with a live preview and a test send; the webhook URL is stored write-only.
- **Updates**: current and newest version, the updater's last result, "check now" and the interval.
- **Preferences**: stats range, 12 or 24 hour clock, date format, landing page, and default theme and sidebar, saved on the server.
- **Export and import**: one JSON file with all of the above, reviewed before it is applied. The webhook URL is included only if you tick a box; Porkbun keys never are.

## Upgrading
Pull the new images; the database migrates itself in an instant, however many probe rows it holds. The access log helper needs the `caddy` and `caddy-ui` services to share the log directory (the example compose file does). If you use the updater, add the shared `updater` folder mount shown in [deploy/compose.example.yml](https://github.com/Kex1016/caddy-ui/blob/main/deploy/compose.example.yml) so Settings can talk to it.
